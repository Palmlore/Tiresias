# Agent reference: building blocks, run phases, external services

The detail behind [AGENTS.md](../AGENTS.md). Read the section a task needs; nothing here is required reading at the start of a session. A PR that adds or changes a module, a phase or an external call updates this file in the same change.

## Building blocks (reuse these; don't rebuild them)
All under `services/agent/src/tiresias_agent/`. Each sponsor client takes an optional `tracer` and degrades instead of crashing (rule 8).

| Module | Use it for |
|---|---|
| `trace.py` | `Tracer(run_id=…, defaults={…}, sink=None)` → `.emit(agent=, action=, status=, **fields)` writes one JSONL line (stdout + `logs/trace-<run_id>.jsonl`); `defaults` are added to every line (Loop A sets `mode="sample"`/`"live"`, ADR-0007); `.span(...)` times a block. Statuses: `success`, `error`, `rejected`, `degraded`. Secret-like keys and Bearer tokens are redacted. `sink` (optional callable) also receives each redacted JSONL line; a failing sink is reported on stderr and never breaks the run. `NullTracer` for tests. **`phase(tracer, name, owner=, every=None)`** (context manager, any tracer): `orchestrator`/`phase_start`, an `orchestrator`/`heartbeat` line every `PHASE_HEARTBEAT_SECONDS` (default 5) while the block runs, then `orchestrator`/`phase_done` with `duration_ms` (status `error` if it raised); every line carries `phase` and `target_agent=owner`. See "Run phases (for UI)". Writes are serialised with a lock (heartbeats come from a thread). |
| `models.py` | Pydantic models for `contracts/openapi/agent.yaml`: `RunRequest`, `RunResult` (leads with `end_state`, `action`; carries `effect`, `information_need`, `why_tree` of `Link`s with `evidence: [EvidenceItem]`, `error`), `InformationNeed` + `EntityHint` (the Loop A → Loop B hand-off), `BranchRequest`, `RunStats`, `ErrorResponse`, … `Entity` is `ticker` / `cik` / `name` (name only used when neither of the others is given). Investigation depth (ADR-0011): `RunOptions.depth` (`Depth` = `quick` (default) / `thorough` / `deep`; `RunOptions.model_lanes` `auto`/`on`/`off` is deprecated: `on` = `deep`, `off` = `quick`, ignored when `depth` is set), `RunResult.depth` and the `POST /runs` 202 body's `depth` (`RunDepth`: `requested`, `requested_by` options.depth/options.model_lanes/MODEL_LANES/default, `effective`, `lanes`, `degraded`, `note`, `expected_wait`), `EntityInfo.expected_first_run_by_depth` (`DepthWaits`: `quick`/`thorough`/`deep` → `ExpectedWait`; `expected_first_run` stays the quick wait). Model lanes (ADR-0010): `Link.proposed_by` (`rules`/`model`) and `Link.model_opinion` (`ModelOpinion`: lane, requested/routed model, provider, receipt id, decision, label, rationale, `grounded`, `agrees`, `rule_decision`, `gate_choice`), `RunResult.action_source` (`template`/`model`) and `action_template`. Directory and scope shapes: `ScopeCheck` (`in_scope`, `reasons: [ScopeReason(type forecast/not-sec-registrant/not-in-sample, message, cue)]`, `alternatives: [Alternative(basis, entity, registered, checks, request)]`, `note`; on `RunResult.scope` only when the check stopped the run), `Suggestion` (kind, basis, question, metric, period, baseline, target, delta, checks, `request`), `EntityInfo` / `EntityList` / `SuggestionList`, `ExpectedWait`. |
| `config.py` | `settings` (env flags), `FIRST_RUN_SECONDS` (expected first-run wait per tier `sample` / `ready` / `searchable`, the measured 0–1 / 3–11 / 15–21 s from docs/measurements/live-any-company.md; re-measure before changing) and `LoopBudgets.from_env()`: `MAX_CAUSAL_DEPTH` (5), `MAX_BRANCHES_PER_LEVEL` (3), `MAX_RETRIES_PER_NODE` (1), `RUN_BUDGET_SECONDS` (600, shared by Loop A and B), `MAX_NEW_SOURCES_PER_RUN` (2, clamped 0..5, field `max_new_sources`), `MAX_MODEL_CALLS_PER_RUN` (12, clamped 0..50, field `max_model_calls`), read at call time and clamped; `model_lanes_mode(env=None)`: `MODEL_LANES` = `auto` (default: the request's depth decides; anything invalid is `auto`) / `on` (`deep` when the request names no depth) / `off` (`quick` at every depth); `DEPTHS` (`quick`, `thorough`, `deep`), `DEFAULT_DEPTH` (`quick`), `MODEL_SECONDS` (model time a depth adds live: 0 / 91–94 / 142–145 s, measured on case 01 on 2026-10-24, ADR-0011; re-measure before changing) and `expected_seconds(tier, depth, sample)` → `(min, max, basis)` = `FIRST_RUN_SECONDS[tier]` + `MODEL_SECONDS[depth]` (`tier=None`: warm or cold, 3–21 s; sample: milliseconds at every depth); `max_over_explained(env=None)`: `MAX_OVER_EXPLAINED` (default `MAX_OVER_EXPLAINED_DEFAULT` = 1.5, i.e. 150% of the root effect, clamped 1.05..10.0, read at call time), the Loop B critic's bound on an over-explaining add-back; `max_cached_facts(env=None)`: `ZETARIS_MAX_CACHED_FACTS` (default 5, clamped 1..50, read at call time), the companyfacts tables a process keeps cached in Zetaris; `LivenessSettings.from_env()`: `ZETARIS_LIVENESS_TTL_SECONDS` (30, 0..600) and `ZETARIS_LIVENESS_TIMEOUT_SECONDS` (3, 0.5..30). |
| `orchestrator.py` | **Entry point: `run_investigation(request, **same kwargs as run_loop_a, discovery=None, zetaris_client=None, data_dir=None)` → `RunResult`** (both also take `lanes=` a `model_lanes.ModelLanes`, built from the request's depth and env when omitted; see `agents/model_lanes.py`; `depth_plan(request, switch=None, unavailable=None)` → `RunDepth`, the depth and expected wait before a run (the 202 body) and on `RunResult.depth`): Loop A, then `LoopB` when Loop A ends at `evidence-frontier` with an `InformationNeed` and a framed effect (otherwise a `loop_b` trace line says why it was skipped). **Loop A only:** `run_loop_a(request, *, source=None, tracer=None, gate=None, budgets=None, logs_dir=None)`. Neither raises for a bad case (structured `error`, or end state `budget`). **Both first resolve the asked entity** (`agents/entity_resolver.py`, phase `resolve_entity`), **then run the scope check** (`agents/scope.py`, phase `scope_check`: out of scope ends at `evidence-frontier` with `RunResult.scope` and nothing registered) and, live, register it if Zetaris lacks it (`onboarder.onboard_entity`, phase `register_entity`, behind the `source` gate, counted in `MAX_NEW_SOURCES_PER_RUN`, deadline = run start + `RUN_BUDGET_SECONDS`); an unresolvable/ambiguous entity, a denial, the cap or a failed registration ends at `evidence-frontier` with the reason, an invalid ticker/CIK is an `InvalidInput` error. Loop A: framer → (hypothesiser → analyst ⇄ critic [→ gate])* → gap analyst → reporter; stops at the first accepted causal link the asker's levers can act on, digs under the strongest breakdown otherwise. Loop B: source scout → onboarder [source gate] → `reconciler` (analyst + critic) → the same asker-relative stopping rule (`actionable` / `branched` / `external-driver`); an unresolvable hint, a gate denial, a failed registration or missing data keeps `evidence-frontier` with `Loop B: <why>` appended to `information_need.reason`; the source cap or the wall clock gives `budget`. **Live only (B-24):** before anything else the run checks Zetaris (`adapters.zetaris.check_liveness`, one `liveness` line; down means the run's client sends nothing more and every read is served from the sample, traced `degraded`); it `pin`s the asked entity's companyfacts table and, after the scout, the Loop B counterparty's in `FACTS_CACHE`, so the cache cap never evicts them while the run goes on; after the `scout` phase it releases the discovery tables the run cached except the asked entity's and the chosen counterparty's (`release_cache`), and at the end of the run releases what is left (except the asked entity's) and unpins. Sample mode does none of this. CLI below. |
| `runs.py` | Run registry behind the HTTP API. `RunRegistry().start(request, run_id=None)` → `RunRecord` (runs in a daemon thread; raises `RunConflict` for a duplicate id, `RegistryBusy` beyond `MAX_CONCURRENT_RUNS`, default 4); keeps the last `RUNS_REGISTRY_SIZE` runs (default 50, oldest finished evicted) and up to `MAX_TRACE_LINES_PER_RUN` lines each (default 5000; the trace file keeps all). `RunRecord.wait(timeout)`, `.follow()` (replay then live lines, for SSE), `.summary()` (the `GET /runs/{id}` body). Adds `api` trace lines `run_accepted` / `run_finished` / `run_failed`. **`runs.execute(...)` is the one place the API calls the pipeline** (`orchestrator.run_investigation`). |
| `app.py` | FastAPI app. `GET /entities?q=&limit=&sample_mode=` and `GET /entities/{cik}/suggestions?role=&limit=&sample_mode=` (`entities.py`; 404 `EntityNotFound` / `EntityNotInSample`, 409 `EntityNotRegistered`, 422 bad CIK; `api` trace lines to `trace-<X-Run-Id>.jsonl`, else one `trace-api-YYYYMMDD.jsonl` per day). `POST /run` = `registry.start` + wait up to `RUN_BUDGET_SECONDS` + 30 s (`runs.wait_budget_seconds()`); `POST /runs` (202 `{run_id, status, events, depth}`, `depth` = `orchestrator.depth_plan`: the depth and its expected wait before the run starts), `GET /runs/{id}`, `GET /runs/{id}/events` (SSE: `event: trace` per JSONL line, `: keepalive` every 15 s idle, one final `event: end`). Every error is the contract's `Error` shape via `error_response(...)`: 422 `ValidationError` (body, JSON or `X-Run-Id`), 404 `RunNotFound`, 409 `RunConflict`, 429 `TooManyRuns`, 500 (pipeline raised), 504 `RunTimeout`, 501 `NotImplemented`. `X-Run-Id` (`[A-Za-z0-9._-]{1,100}`) is honoured and echoed. CORS is off unless `CORS_ALLOW_ORIGINS` is set. `GET /health` never waits on a dependency: `zetaris_cache` (the warm on start) and `zetaris` (`zetaris_health()`: the last liveness probe `state` `off` in sample mode / `not-checked` / `alive` / `down` / `inconclusive`, with `reason`, `checked_at`, `duration_ms`, plus `cached_facts`, `max_cached_facts`, `pinned`; contract `ZetarisHealth`). |
| `entities.py` | Entity directory behind the two `GET /entities` endpoints. `list_entities(q, sample=, source=, discovery=callable, tracer=, limit=)` → `EntityList`: tier `ready` = registered (live: facts table + filings view + a supported metric view, names from `sec_tickers`; sample: the slice), tier `searchable` = live `sec_tickers` matches for `q` (ticker, CIK or name, 2+ characters) and partly registered entities matching it; each with `expected_first_run` from `FIRST_RUN_SECONDS` (quick) and `expected_first_run_by_depth` (`expected_by_depth(tier, sample)`, via `config.expected_seconds`). Sample mode lists only the slice and says why in `note`; an outage serves the sample, `degraded: true`. `suggestions(cik, ...)` → `SuggestionList` for a ready entity (`suggester.suggest`), else `DirectoryError(status, type, message)`. |
| `agents/suggester.py` | Questions from an entity's own data. `suggest(entity, source, tracer=, asker=, limit=, sample_mode=)` → `SuggestResult(suggestions, considered, rejected)`: per `knowledge.SUGGESTED_METRICS` (Revenues, NetIncomeLoss), annual facts only: **restatements** (first time two consecutive annual filings disagree on a fiscal year; newest restating filing first, at most `MAX_RESTATEMENTS`), the **largest changes** (`CHANGES_PER_METRIC` by absolute delta) and the **lowest / highest value** (only if it is the extreme of every reported annual value and the year frames). Every candidate is a `RunRequest` **validated by the framer itself** (kind as intended, relative change ≥ `MIN_RELATIVE_CHANGE` 1%); neutral wording (differ / rise / fall / was). `latest_change(entity, source, metric, asker=)` → the most recent validated change (the scope check's past-period alternative). `CachingSource` memoises the series. |
| `agents/scope.py` | Scope check after `resolve_entity`, before Loop A. `check(request, resolution, sample=, source=, discovery=callable, tracer=, today=None)` → `ScopeCheck`. Reasons: `forecast` (`forward_cue(question)`: strong cues "what if", "will", "going to", "suppose", "what/how would" or "would … if" without a "have" within three words, always; weak cues "forecast", "predict", "projection", "outlook", "expect … to", "next year/quarter" only when the question is not framed as explaining the past, "Why did …"; or a period ending after today), `not-sec-registrant` (live `EntityNotFound` with zero `sec_tickers` rows, never when degraded), `not-in-sample` (sample). Up to `MAX_ALTERNATIVES` (3) runnable `RunRequest`s: registrants **named in the question** (capitalised phrases, `name_phrases`, each matching exactly one CIK in `sec_tickers`), the **same entity, past period**, **same SIC peers** among registered entities (`discovery.registrant` → `sic`, at most `MAX_PEER_PROBES`, cached). Registered → `suggester.latest_change`; unregistered (live) → the fiscal year between its two latest 10-K report dates, `registered: false` (the run registers it). |
| `agents/framer.py` | `frame(request, source, tracer)` → `Frame`: a like-for-like effect. `restatement` when `compare.filing_a/filing_b` are `"<form> filed YYYY-MM-DD"` (same period, two filings), else `change` (period vs prior period, both from the first annual filing reporting the period). Raises `FrameFailure` (metric not in sources → evidence-frontier) or `LoopError`. |
| `agents/hypothesiser.py` | Rule-based (ADR-0007). `propose(frame, parent, path_variables, max_branches=, tracer=, exclude=)` → `Candidate`s from generic rules in `agents/knowledge.py`: hierarchy children, event concepts (goodwill impairment), 8-K items (2.01 disposal, 4.02 non-reliance / 10-K/A), concept switch, restated comparative. No cycles, capped. When the model lanes are on, the orchestrator then asks `model_lanes.propose` to fill only the slots the rules left free under `MAX_BRANCHES_PER_LEVEL` (also when the rules found none). |
| `agents/analyst.py` | `measure(candidate, frame, source, attempt=, scope=, tracer=)` → `Measurement`: queries only through `EvidenceSource`, keeps SQL + filter + rows per query, computes the candidate's effect and the counterfactual (intervention re-query on the returned rows). Scopes: `broad` → `window` → `relaxed` (set by the critic). |
| `agents/critic.py` | Pure rules over a `Measurement`: `judge(candidate, m, frame, retries_left=)` → `Verdict` (`accept` / `prune` / `retry` / `frontier`, label, evidence status, share vs the root effect); `apply_gate(verdict, choice)`. Thresholds in `agents/common.py` (`MOST_OF_EFFECT`, `MIN_SHARE`, …). The final verdict (not a retry) may get the deep lane's `model_lanes.second_opinion`; the rule verdict decides, a disagreement goes to `critic_escalation` (proposal `keep-rule`), and `trace_verdict` runs after that, so the critic's line shows the decided verdict. |
| `agents/gap_analyst.py` | `for_candidate(frame, node, tracer)` / `for_variable(...)` / `for_breakdown(frame, ruled_out, tracer)` (every tested candidate was a ruled-out accounting/filing event, `knowledge.EVENT_RULES`: says what was ruled out and asks for `<metric> by segment or product`, relation `same entity, breakdown`; Loop B is skipped for it) → `InformationNeed` (variable + aliases, entity hint from the run's own evidence, period, join key, expected magnitude, the intervention test to run). **Loop B consumes this.** |
| `agents/entity_resolver.py` | Before Loop A. `resolve(request, source=, sample=, tracer=, discovery=callable, views=callable)` → `Resolution(entity, registered, reason, error_type, evidence, candidates)`. Registered entities first (CIK, ticker, then name; live also needs the filings view and a metric view). Sample: anything else is `EntityNotInSample`, with a reason that lists the slice's entities and how to run live. Live: `discovery.lookup(tickers=, ciks=)` or `.search(name)` over the Zetaris `sec_tickers` view; one CIK resolves it, none is `EntityNotFound`, several (or a ticker/CIK that disagree) is `EntityAmbiguous`. Object names use `zetaris.object_ticker` (`BRK-B` → `brkb`). |
| `agents/source_scout.py` | Loop B. `resolve(need, discovery=, tracer=)` → `ScoutResult(entity, template, reason, evidence, candidates)`. Rule-driven, catalog-only: the hint must name an 8-K 2.01 filing; the source row comes from `discovery.lookup(...)`. **Candidates come from filing evidence first**: `discovery.filers_naming(phrase, REGISTRATION_FORMS, …)` finds filers whose Form 10 (10-12B/10-12G) in the `REGISTRATION_LOOKBACK_DAYS` (540) before the disposal contains the source's name as it was then (`search_phrase`: former name in force, legal-form words dropped), at most `MAX_NAMED_CANDIDATES` with ≥ `NAMED_SHARE` of the top filer's documents; then `discovery.brand(words)` rows carrying the source's brand (a ranking signal; the only candidates in sample mode for a search the slice does not cache); ≤ `MAX_CANDIDATES` in all. A candidate qualifies if its `sec_submissions` show it became a separate registrant at that disposal (registrant by the date, no 10-K before it, or one 10-K after its own recent Form 10, its own 8-K within `SEPARATION_WINDOW_DAYS`). If none qualifies, a second search over 8-Ks within that window finds a buyer: an existing registrant with item 2.01 there is refused as *a sale to an existing company*. Rank: Form 10 naming, item 5.01, brand, distance; a tie on all is `ambiguous`, none is a refusal, both with the phrase searched and the candidates checked. `assess()` and `pick_template()` (registrable XBRL template with the fewest registrations: `sec_companyfacts`) are pure. |
| `agents/onboarder.py` | Loop B. `onboard(scout, need, gate=, registry=, cap=, sample=, tracer=, client=None, data_dir=None)` → `Registration(status registered/degraded/denied/capped/failed, mode zetaris/sample)`: cap check → dry run (`bootstrap_plan(..., tables=("facts",))`, nothing executed) → `source` gate (options `register`/`deny`, proposal `register`) → live `bootstrap(...)` one statement at a time + view refresh, or a **sample-mode registration** (traced `registration: "sample"`, Zetaris not called). Outage → degraded to the sample; non-recoverable → failed. `Registry(source, asked, onboarded=())` is what the Loop B analyst queries: it raises `SourceError` for any entity not registered in this run; `onboarded` seeds the cap count (the asked entity, if this run registered it). **`onboard_entity(entity, metric=, gate=, used=, cap=, tracer=, client=, deadline=, clock=)`**: the asked entity, live only: cap → dry run → `source` gate (`context.scope: "asked_entity"`) → `bootstrap` of both raw tables, their caches, the concept views (`CONCEPT_SLUGS` + the metric and its aliases) and the filings view; no sample fallback (the slice only holds the showcase entities). Both forward `deadline` to `bootstrap`. `onboard` also passes `protect=registry.allowed`, so its companyfacts `CACHE TABLE` never evicts the asked entity under `ZETARIS_MAX_CACHED_FACTS` (`onboard_entity` registers the asked entity, which bootstrap protects itself). |
| `agents/reconciler.py` | Loop B analyst + critic. `measure(frame, need, entity, source, node_id=, tracer=)` → `Reconciliation` (the entity's first annual value of the metric for the period, `restated + disposed` counterfactual, residual amount); `judge(frame, r, bound=None)` → (`Verdict`, signed residual share): accept `evidenced` if it explains ≥ `MOST_OF_EFFECT` and the add-back is within `RECONCILE_TOLERANCE` (5%) of the original (over-explaining included, case 02); when it over-explains beyond tolerance, ask the `critic_escalation` gate with proposal `accept-capped` up to `bound` (default `MAX_OVER_EXPLAINED`, 150%) and proposal `prune` beyond it (reason: "the add-back of X explains N% of the change, beyond the 150% bound … so the match is likely wrong"), so under `auto` a gross over-explanation ends at `evidence-frontier` and only a scripted/interactive `accept-capped` keeps it; prune below `MIN_SHARE`, frontier when the data or a restatement frame is missing. Traced as `analyst`/`critic` with `loop: "B"`; the critic line carries `share_explained`, `raw_share`, `over_explained_bound` and `gate_choice`. |
| `agents/reporter.py` | `build(...)` → `RunResult`; action text per (cause category, asker lever family) from `agents/knowledge.py` (`RECONCILED_ACTIONS` for a Loop B `reconcile` link, whose residual is signed). `link(node)` carries `proposed_by` and `model_opinion`. With the lanes on, the orchestrator may swap `action` for `model_lanes.draft_action` (then `action_source: "model"`, template in `action_template`). |
| `agents/model_lanes.py` | Model lanes (ADR-0010): the model proposes, the rules and the data decide. `DEPTH_LANES` (ADR-0011): `quick` → no lane, `thorough` → `critic`, `deep` → `hypothesiser`, `critic`, `reporter`. `requested_depth(depth, model_lanes, env=None)` → `(depth, requested_by)`. `resolve(depth=None, *, model_lanes=None, sample=, config=, max_calls=, env=None)` → `LaneSwitch(enabled, mode, reason, lanes, requested, depth, requested_by, degraded)`, first match wins: sample mode → no lane at any depth; `MODEL_LANES=off` → `quick`; else `RunOptions.depth`, else the deprecated `RunOptions.model_lanes` (`on` = `deep`, `off` = `quick`), else `MODEL_LANES=on` = `deep`, else `quick`; a depth with lanes and cap 0 or no `NightshiftConfig.configured` → `quick`, `degraded` (`.announce()` then adds one `model_lanes`/`degrade` `degraded` line). `.allows(lane)` gates each lane; `.unavailable` is set when Nightshift failed mid-run. `ModelLanes(tracer=, switch=, config=, max_calls=, deadline=, clock=, transport=None, run_id=)`: `.ask(lane=, agent=, action=, system=, user=, node_id=)` → `(parsed JSON, ModelReply)` or `None` (off, cap reached → one `model_lanes`/`cap` line, < 5 s of run budget left → one `budget` line, `ModelUnavailable` → one `<agent>`/`degrade` `degraded` line and the lanes stay off for the run, an unusable reply → `<agent>`/`model_reject`); never raises; each call is a `model_call` phase and the client's one line per call; `.calls` / `.tokens` feed `stats.model_calls` / `stats.tokens`; `.announce()` writes `model_lanes`/`mode` at run start (`lanes` on/off and why). Lanes: `propose(lanes, frame, parent, rule_candidates=, path_variables=, exclude=, free=, tracer=)` (fast) → validated `Candidate`s (`proposed_by="model"`, rule `event_concept` or `filing_event`) from `vocabulary(frame)` only (registered `CONCEPT_SLUGS` + event concepts minus the metric and its aliases, plus the filing events for the effect's kind and family); `second_opinion(lanes, cand, m, v, frame, tracer)` (deep) → `ModelOpinion` (`agrees` vs the rule verdict; a rationale with a number not in the measurement is dropped); `dissent_request(v, opinion)` (gate options `keep-rule` and, unless the rules pruned, `prune`); `draft_action(lanes, template, context, tracer)` (fast) → wording or `None` (`ungrounded_numbers` / `ungrounded_names` against the template and root cause). Tests: `tests/test_model_lanes.py` (fake Runtime via `httpx.MockTransport`). |
| `agents/knowledge.py` | Generic SEC/US-GAAP knowledge only (concept families and components, event concepts, 8-K item codes, lever families, action templates). Never entity-specific; a guard test greps agent logic for case literals. |
| `gates.py` | `Gate(mode, tracer=, policies=, scripted=, ask=)` → `.decide(GateRequest(gate=, question=, options=, proposal=, node_id=, requested_by=))` → `GateDecision`. Modes `auto` (policy, default: follow the proposal), `scripted` (`RunOptions.decisions["<gate>:<node_id>"]` or `["<gate>"]`), `interactive` (`ask` callable). Traced with `gate`, `gate_mode`, `decided_by`. Loop A uses `critic_escalation`; source and memory gates should reuse it. |
| `adapters/zetaris.py` | Evidence. `make_source(sample_mode, tracer)` returns an `EvidenceSource`: `SampleSource` (reads `data/sample/`) or, live, `FallbackSource(LiveZetarisSource, SampleSource)`, which falls back to the sample per call on a recoverable `SourceError` and traces `degraded` with its `cause`; a known fatal one is raised, never served from the sample. **Error classification** (one place in `zetaris.py`; table in [zetaris/README.md](../zetaris/README.md#error-handling)): `SourceError.cause` is one of `CAUSES`: `outage` (timeout, connection error, 5xx; the only cause retried), `dead_engine`, `unclassified` (recoverable: any failure no rule identifies, i.e. an unseen 4xx body, an empty 4xx body, a non-JSON/HTML/truncated reply, a 2xx that is not `{headers, data}` lists, a row that does not parse (`_typed_rows`), or any other exception inside a live read, which `FallbackSource` / `FallbackDiscovery` wrap except `BEFORE_SENDING_ERRORS` (`ValueError`, `KeyError`: input or template faults before sending, a missing template as `TemplateError`, raised as is; a transport `OSError` is wrapped)), and the non-recoverable `auth` (401/403, `AUTH_SIGNATURES`), `sql` (`SQL_SIGNATURES`: ParseException, AnalysisException, `FIELD_NOT_FOUND`, `TABLE_OR_VIEW_NOT_FOUND`, ...), `refused` (`REFUSED_SIGNATURES`, or an unclassified 4xx the caller's `expected=` recognises) and `fatal` (raised by our own checks). `classify_reply(status, body)` decides a failed reply; `unclassified(message, status_code=, excerpt=)` builds one; `err.trace_fields()` gives `cause`, `http_status`, `excerpt` (scrubbed, ≤ `EXCERPT_CHARS` 160), carried by the client's `error` line and the fallback's `degraded` line; bootstrap `failed` entries carry `cause`. The liveness probe treats `unclassified` as `inconclusive`, not down. Tests: `tests/test_zetaris_matrix.py`. Methods return `Evidence` (a list of `Fact` / `Filing` / `Entity` carrying `.sql`, `.source`, `.degraded`). Concept aliases (`Revenues` ↔ `RevenueFromContract…`) resolve automatically. `bootstrap(client, entities=, concepts=, tables=, discovery=False, deadline=None, clock=)` registers sources from `zetaris/sql/` (idempotent, never drops; `tables` ⊆ `("facts", "submissions")`, failed entries carry `recoverable`; `discovery=True` adds the `sec_tickers` table + cache + view; past `deadline` the remaining statements are `skipped` with `budget: true`, and each statement's timeout is capped at the time left); the CLI passes `discovery=True`, the onboarder reuses it. Behaviour worth knowing before you change these modules:
- The run registry is in memory and per process: `GET /runs/{id}` forgets runs after a restart or once `RUNS_REGISTRY_SIZE` newer runs finished (trace files stay in `logs/`). A run that outlives `POST /run`'s wait (504) keeps running in its thread; poll `GET /runs/{id}`.
- Suggestions are derived from the data, so the demo chooses which ones to feature; the engine never tilts them.
- The agent image (`compose.yaml`: `context: .`, `dockerfile: services/agent/Dockerfile`) mirrors the repo under `/app` (`/app/services/agent`, `/app/data/sample`, `/app/zetaris/sql`, `/app/catalog`, `/app/input_examples`), so the package's repo-relative defaults resolve; `SAMPLE_DATA_DIR`, `ZETARIS_SQL_DIR` and `LOGS_DIR=/app/logs` are also set.
- The CLI resolves a relative request path against the cwd, then the repo root, and writes traces to `<repo>/logs/` unless `LOGS_DIR` or `--logs-dir` is set.

## Run phases (for UI)
Every slow phase is bracketed by trace lines on the SSE stream (`GET /runs/{id}/events`): `agent: "orchestrator"`, `action: "phase_start"` / `"phase_done"`, field `phase` (below), `target_agent` (the agent doing the work), `duration_ms` and `status` on `phase_done` (plus `outcome` / `end_state` where useful); while a phase runs, `action: "heartbeat"` with the same `phase` and `elapsed_ms` every `PHASE_HEARTBEAT_SECONDS` (default 5), so no wait is silent for more than ~5 s. Nested phases close before their parent. Measured live on 2026-10-23 ([docs/measurements/live-any-company.md](docs/measurements/live-any-company.md)); sample mode runs every phase in milliseconds.

| `phase` | Owner (`target_agent`) | When | Typical live duration |
|---|---|---|---|
| `resolve_entity` | `entity_resolver` | every run | 0.1–0.6 s |
| `scope_check` | `scope` | every run | ~1 ms in scope; out of scope (live, 2026-10-23) 0.4 s, or 1.8 s when an alternative's submissions discovery table is created first |
| `register_entity` | `onboarder` | live, asked entity not in Zetaris yet (cold) | 11.8–15.6 s (one companyfacts `CACHE TABLE`, 7–12 s, is most of it); absent when warm |
| `loop_a` | `orchestrator` | every run past entity checks (includes `frame`) | 3–10 s (0.2 s when the metric is not found) |
| `frame` | `framer` | inside `loop_a`: first evidence query | 0.2–2.6 s |
| `loop_b` | `orchestrator` | Loop A ended at a frontier with a need | 0.0–3.6 s warm; 11.4 s with a cold onboard (14.4 s before the scout fix) |
| `scout` | `source_scout` | inside `loop_b` | 0.0–0.5 s with no new candidate; 1–2.5 s with new candidate submissions tables |
| `onboard` | `onboarder` | inside `loop_b`, scout resolved | 1.0–1.6 s if the table exists; 8.1 s cold |
| `reconcile` | `analyst` | inside `loop_b`, registered | 0.5–1.4 s |
| `model_call` | the calling lane (`hypothesiser`, `critic`, `reporter`); the line also has `lane` | live runs at depth `thorough` (critic only) or `deep` (all lanes; ADR-0011; the default `quick` has none), one per Nightshift call, nested in `loop_a` or after `loop_b` | 24–41 s deep, ~50 s fast for the action wording (live, 2026-10-24, case 01; the probe's one-word reply takes 2–9 s) |
