# ADR-0010: Model lanes through Nightshift: the model proposes, the rules and the data decide

Status: accepted (2026-10-24). **Addendum (2026-10-24): the switch below is replaced by the investigation depth of [ADR-0011](ADR-0011-investigation-depth.md).** Live runs now default to rules only (`quick`); the user asks for `thorough` (the critic lane) or `deep` (all three lanes) per question and is told the expected wait first, because the lanes took 91–94 s (three deep critic calls) plus about 51 s (the wording call) on case 01, 169–173 s end to end, against 3–21 s rules only. `MODEL_LANES` stays as an operator override (`off` forces rules only; `on` = `deep` when the request names no depth), `RunOptions.model_lanes` is deprecated, and sample mode makes no model call at any depth. The lanes themselves are unchanged.

Context: the event rules make Meterless Nightshift the primary model provider for real model calls, and NVIDIA Nemotron powering a feature is a bonus. Until now no agent called a model (`stats.model_calls` was 0): the hypothesiser, critic and reporter are rule-based (ADR-0007). A model must not become a way to put unevidenced claims in the report (ADR-0004: every accepted link passes the critic's tests on SQL rows), and judges run sample mode with no keys.

Nightshift 1.2.1 routes on its own: a request names a lane (`meterless/fast` or `meterless/deep`), and explicit model ids are not honoured. On 2026-10-24 the receipts named `nvidia/nemotron-3.5-lightning-30b-a3b`, `nvidia/nemotron-3.5-super-vl-120b-a12b` and `nvidia/nemotron-3-ultra-550b-a55b` for the same lanes on different calls.

Decision: three optional model lanes (`agents/model_lanes.py`), each bounded and validated:
- **Hypothesiser lane (fast).** After the rule candidates for a level, the model may fill the branch slots the rules left free (`MAX_BRANCHES_PER_LEVEL` still caps the level). It may only name items from the evidence vocabulary the source can query: the registered concepts (other than the metric and its aliases) and the 8-K filing events that apply to the effect's kind and metric family. A proposal outside that vocabulary, on the path, already tested or proposed, with a bad sign or category, or over the free slots is dropped with a `model_reject` trace line. A valid one becomes an ordinary `Candidate` (`proposed_by: "model"`, a templated claim, the model's note only in the trace) and goes through analyst ⇄ critic like any other. Generic knowledge (`agents/knowledge.py`) wins over the model on a known concept's sign and category.
- **Critic lane (deep).** After the rule critic's final verdict on a link, the model gives an independent judgement (label breakdown/causal/background, accept/prune, a one-paragraph rationale) from the measurement's own numbers; it is not shown the rule verdict. The rule verdict stays the decision. A disagreement goes to the existing `critic_escalation` gate with the proposal `keep-rule`, so the auto policy follows the rules; a scripted or interactive gate may prune on the model's dissent, never accept what the rules did not. Both opinions are recorded: `Link.model_opinion` (decision, label, rationale, routed model, receipt id, `agrees`, `gate_choice`) and the trace. A rationale that quotes a number not in the measurement is dropped (`grounded: false`).
- **Reporter lane (fast).** The model may reword the template action in plain language. Its draft replaces `RunResult.action` only when it adds no number and no capitalised name absent from the template and the root cause (`action_source: "model"`, the template kept in `action_template`); otherwise the template stays.

Switch: `MODEL_LANES` = `auto` (default: on when `SAMPLE_MODE=false` and Nightshift is configured, off in sample mode), `on`, `off`; `RunOptions.model_lanes` overrides it per run. Bounds: `MAX_MODEL_CALLS_PER_RUN` (default 12, clamped 0..50, counted in `stats.model_calls`), the run's wall-clock budget (no call starts with under 5 s left, and each call's timeout is capped at the time left), and `MODEL_TIMEOUT_SECONDS`. `ModelUnavailable` (offline, timeout, unauthorised) switches the lanes off for the rest of the run with one `degraded` line; an unusable reply is a `rejected` line for that step. The run never fails because of a model.

Every model call writes one trace line (agent and action of the calling lane, `lane`, `requested_model`, `routed_model`, `provider`, `latency_ms`/`duration_ms`, `receipt_id`, status, a short output summary; secrets redacted), inside a `model_call` phase so a UI sees heartbeats. **`routed_model` is always logged from the receipt** because the requested id says only which lane was asked, not which model answered.

Consequences:
- Sample mode (the judges' quickstart) makes zero model calls by default and gives the same end states and why-trees as before; `MODEL_LANES=on` with a configured Runtime runs the lanes on the cached rows too.
- In live mode a model can widen the search and add a second opinion, but every accepted link still rests on SQL rows and the critic's tests, so the end state is reproducible from the trace.
- Model calls dominate a live run's wall time (24–41 s per deep call measured on 2026-10-24, against 9–11 s for the whole rule-only GE run), so the cap and the run budget matter.
- The hypothesiser lane only acts where the rules leave a free slot; on the three examples the rules fill the root level, so it acts at deeper levels or for other questions.
